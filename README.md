# 会话清道夫（astrbot_plugin_session_janitor）

一个给 AstrBot 用的核心库清理插件：扫描已退群、已删好友、过期临时会话留下的
会话数据，先预览、再备份、最后删除，并支持一键回滚。

**只操作 AstrBot 核心库 `data/data_v4.db`，不读取、不修改任何插件数据。**
所有管理操作都在 Dashboard 的 Web 面板里完成，不需要记命令。

## 功能

- **数据库体检**：首屏展示 `data_v4.db` 文件大小、核心库相关表总行数、
  默认可清理行数、可选清理的 `provider_stats` 行数、候选会话数和预计可回收空间；
  可下载体检报告 JSON，并可一键带着 `provider_stats` 重新生成清理预览。
  体检只读，不会删除数据，也不会自动 VACUUM。
- **扫描**：读取当前 QQ 群/好友列表，对比核心库里的会话数据，自动分类：
  - 已退群：群已不在当前群列表里，默认勾选；
  - 已删好友 / 好友列表外：私聊对象已不在好友列表，默认不勾选；
  - 过期临时会话：好友列表外且超过 30 天未活跃，默认不勾选；
  - 白名单：命中白名单的会话永不清理。
- **会话详情**：群号/QQ号、群名/QQ昵称、UMO、别名、最后活跃时间、各核心表
  残留条数、偏好记录、核心库平台消息历史，以及**可展开查看的核心库完整对话记录**。
- **清理预览**：只读展示“如果清理会处理什么”，支持单独勾选 `provider_stats`。
- **执行清理**：后台任务 + 实时进度；执行前自动做整库快照和逐行 JSON 备份；
  删除在单事务内完成，失败自动回滚。
- **备份与回滚**：每次清理生成一份备份，可在面板里一键回滚；回滚前会自动备份
  当前数据库，旧 V0.3 备份里的插件文件会被跳过。
- **Web 设置**：平台 ID、临时会话阈值、扫描超时、白名单、备份保留份数等
  直接在面板里修改并保存；平台 ID 会自动检测 AstrBot 已加载的平台实例并以
  下拉框列出，检测不到时回退为当前配置值。
- **定时自动清理**：开启后按设定间隔扫描，只清理已退群会话；执行后写日志并按
  通知配置发送摘要。默认关闭，不会自动清理已删好友/临时会话。
- **立即运行一次 / 测试通知**：不用等定时，可手动触发一次自动清理；通知目标配好后
  可直接发一条测试通知验证。
- **扫描差异 / 明细导出**：概览显示与上次扫描相比的新增候选、已解决候选和状态变化；
  清理完成后可下载本次清理明细 JSON。
- **可见反馈**：刷新、筛选、重新生成、保存、清理等所有按钮都有“处理中/完成/失败”
  状态，不再出现点了没反应的情况。
- **备份目录体积**：备份列表显示所有快照占用的磁盘空间，避免忽略“快照=库大小”。
- **VACUUM 提示**：清理后若空闲页占比高，会提示在空闲时段手动 VACUUM。

## 安装

### 安装方式

插件市场上架准备中；当前请使用下面的手动安装方式。市场上架后会在这里补充
「Dashboard → 插件 → 插件市场搜索『会话清道夫』」的说明。

### 市场安装须知（三个限制）

1. 回滚会覆盖同主键的新数据，除非在冲突提示里选择“跳过冲突”；默认不会静默覆盖。
2. “预计可回收空间”是按表平均行长做的粗略估算，实际以 VACUUM 后为准。
3. 插件不自动执行 VACUUM；需要真正缩小数据库文件时请自行在空闲时段执行。

### 手动安装（当前推荐）

把整个目录放到：

```text
AstrBot/data/plugins/astrbot_plugin_session_janitor/
```

重启 AstrBot 或在 Dashboard 插件页重载该插件，然后打开：

```text
Dashboard → 插件 → 会话清道夫
```

无需额外 Python 依赖。

## 使用说明

### 数据库体检看什么

概览页顶部的「数据库体检」卡片会显示：

- `data_v4.db` 文件大小（含 WAL 大小）；
- 核心库相关表的总行数（会话别名、对话记录、偏好、调用统计、平台消息历史）；
- **默认可清理行数**：当前默认勾选的已退群会话里、不含 `provider_stats` 的行数；
- **可选调用统计行数**：所有候选会话里的 `provider_stats` 行数；
- **候选会话数**和**预计可回收空间**。

预计可回收空间按表平均行长估算（优先 `dbstat` 表页/行数，退化为按列长度总和），
仍是粗略值；`provider_stats` 每行很小，不要用行数直接乘文件大小。
SQLite 删除行后文件不会自动缩小，真正释放磁盘空间需要执行 `VACUUM`；
插件不会自动 VACUUM。点「生成体检报告」可以下载当前数据 JSON；
点「包含调用统计重新预览」会自动勾选 `provider_stats` 并跳到清理预览。

### 主要按钮分别做什么

| 按钮 | 作用 | 会不会重新扫描群列表 |
|---|---|---|
| 生成体检报告 | 下载当前数据库体检数据 JSON（只读） | 不会 |
| 包含调用统计重新预览 | 勾选 `provider_stats` 后重新计算清理预览 | 不会 |
| 开始扫描 | 重新读取当前 QQ 群/好友列表，再扫描核心库，更新所有标签页 | 会 |
| 刷新当前页 | 只重新读取最近一次扫描结果并重画当前页 | 不会 |
| 重新生成预览 | 按当前 `provider_stats` 开关重新计算预览 | 不会 |
| 筛选 | 在最近一次扫描结果里按状态/类型/关键词过滤 | 不会 |

### provider_stats（调用统计）是什么

`provider_stats` 是 AstrBot 每次调用模型时记下的**用量流水**：哪个会话用了哪个模型、
多少 token、耗时多久。删除它只会丢失历史用量统计，**不影响聊天记录、偏好设置、
白名单或机器人运行**。因此默认不清理，需要时在预览/执行清理页单独勾选。

### 清理确认词

执行清理需要输入中文四个字：

```text
确认删除
```

完成后会自动刷新概览、候选列表和备份列表。

回滚需要输入中文四个字：

```text
确认回滚
```

回滚前会自动备份当前数据库；同一份备份回滚过一次后不能再次回滚。
如果检测到同主键已经产生新数据，会先询问“跳过冲突”还是“强制覆盖”，不会静默覆盖。

### 自动清理

在「设置」页开启「自动清理」，并设置扫描间隔（分钟）。开启后：

- 每隔设定时间扫描一次当前群/好友列表和核心库；
- **只清理「已退群」且仍有核心数据的会话**；
- 已删好友、过期临时会话不会被自动清理；
- 默认不删 `provider_stats`，可在设置里单独打开；
- 删除前照常生成整库快照 + 逐行备份；
- 执行结果写入「扫描日志」，并按通知配置发送摘要。

自动清理默认关闭。设置页会显示当前状态、下次运行时间、上次运行结果。
可以点「立即运行一次」马上执行一次（会二次确认并先备份）；通知目标保存后，
可以点「发送测试通知」验证是否能收到。
通知目标留空时，会尝试发送给 AstrBot `admins_id` 里的数字 QQ 管理员；
没有可用的管理员 QQ 时只写日志，不影响清理。

## 常见问题

### 为什么候选有 9 个，清理预览却是 0 行？

候选里可能大部分**只剩 `provider_stats` 调用统计**。该表默认不清理，所以预览默认
不计入这些行；面板会把这类条目默认隐藏并标注“仅剩调用统计”。如果你确认要连用量
统计一起清掉，勾选「包含 provider_stats」或「显示仅剩调用统计的条目」，再执行一次
清理即可。

### 为什么清理后候选列表里还有条目？

同上，大概率只剩 `provider_stats`。这是预期行为，不是清理失败。

如果你确认要连用量统计一起清掉，勾选「包含 provider_stats」或
「显示仅剩调用统计的条目」，再执行一次清理即可。

### 为什么详情页看不到对话记录？

AstrBot 核心库的 `conversations` 表只保存**真正和机器人进行过 LLM 对话**的会话，
数量通常很少（例如只有 3 条）。QQ 群/好友的普通聊天正文不在核心框架里；
本插件不读取任何插件数据，所以只能显示核心库实际保存的内容。

有记录的会话在会话列表名称旁会显示「有对话记录」标记；点「详情」后可以展开
「查看对话记录」，看到和 Dashboard「数据与日志 → 对话」相同的聊天内容。

### 候选行数是聊天消息条数吗？

不是。它是这个会话在核心库里匹配到的**数据库行数**（会话别名、偏好、调用统计等），
用来判断清理规模，不等于聊天消息数量。

### “已删好友”和“临时会话”怎么区分？

历史数据无法可靠区分两者。插件把好友列表外、未超过 30 天阈值的私聊标为
「好友列表外」，超过 30 天的标为「过期临时会话」，两类都默认不勾选，
需要你手动确认后再清理。

### 会不会误删插件数据？

不会。插件的扫描、详情、清理、回滚都只操作 `data_v4.db`；
`livingmemory`、群日报、`message_stats` 等插件数据一律不读取、不修改。
旧 V0.3 备份里如果带有插件文件，回滚会跳过它们并在结果里提示“跳过旧插件文件 N 个”，
不会写回插件目录。

### 为什么有些偏好记录在详情里提示“跨会话共享”？

同一行偏好可能被多个群/会话引用。整行删除会误伤其他会话，所以这类记录默认跳过，
不会自动清理；详情里会标注“跨会话共享，不会自动清理”。

## 安全设计

1. 扫描阶段数据库只读。
2. 群/好友列表获取失败、超时或返回空列表时立即停止扫描，不产生候选。
3. 只处理 `GroupMessage` / `FriendMessage`；WebChat、系统会话、其他平台跳过。
4. 清理前生成整库快照 + 逐行 JSON 备份；整库快照失败会中止清理。
5. 删除单事务，失败回滚；回滚按逐行 JSON 恢复，不直接替换正在使用的数据库文件。
6. 回滚只恢复核心库行；旧 V0.3 备份里的插件文件会跳过，不写回插件目录。
7. 回滚前自动备份当前数据库；同一份备份不能重复回滚。
8. 跨会话共享的偏好行默认跳过，避免整行删除误伤其他会话。
9. 白名单会话永不清理。
10. 回滚前按主键检测冲突；默认不覆盖，用户需选择跳过冲突或强制覆盖。
11. 删除量 ≥500 时在提交前执行 `PRAGMA quick_check`；失败自动回滚并标记备份失败。
12. 回滚只允许五张核心表，并校验列名；非核心表/未知列拒绝写入。

## 已知限制

- 仅支持 aiocqhttp（QQ OneBot）；QQ 官方接口无历史消息/成员列表，不承诺支持。
- 只清理 AstrBot 核心库 `data_v4.db`，不读取也不修改任何插件数据。
- `platform_sessions` 表当前不处理；面板会标注“已跳过”。
- 修改平台实例 ID 后，旧 UMO 仍带原平台 ID，可能扫描不到；需要改回原 ID 或手动处理。
- 好友列表为空时允许扫描并显示警告；私聊会话按“好友列表外”处理且默认不勾选。
- 自动清理的“上次运行/上次结果/下次运行”会写入插件数据目录的
  `automation_state.json`，0.7.1 起重启后会恢复未过期的 `next_run`；历史记录仍保留在扫描日志。
- SQLite 删除行后不会自动缩小数据库文件；需要回收磁盘空间时可手动 VACUUM。
- **0.7.1 回滚发现同主键冲突时不会静默覆盖**：会先要求选择“跳过冲突”或
  “强制覆盖”，结果里给出 `skipped_conflicts` / `overwritten` 计数。
- **0.7.1 回滚前会校验 `rows.json`、库文件和安全快照**；缺失/损坏/`created`
  状态直接中止，不会假成功，也不会创建空库。
- **删除量 ≥500 行时于 `commit()` 前执行 `quick_check`**；失败自动回滚并把
  备份标记为 `failed`。大库校验可能耗时数秒，期间 AstrBot 写入会短暂等待；
  耗时记录在备份 manifest 的 `quick_check_ms`。阈值 500 固定，如需更快可调高
  源码里的 `QUICK_CHECK_THRESHOLD`。
- **0.7.1 回滚只允许五张核心表并校验列名**；备份里的非核心表/未知列会被拒绝。
- **0.7.1 要求平台适配器必须是 `aiocqhttp`**；`webchat` 等不支持项在设置页禁用，
  选错平台会得到明确错误。
- **0.7.1 会自动清理前比较上次扫描**：群/好友数量骤降 >30% 时跳过自动清理并写日志；
  手动扫描会显示警告，请确认接口结果后再清理。
- **“预计可回收空间”仍是粗略估算**：0.7.1 按表平均行长（dbstat/列宽）估算，
  实际以 VACUUM 后为准；`provider_stats` 每行很小，不要按行数直接乘文件大小。
- **整库快照包含完整 `data_v4.db`（含私密聊天/人设数据）**：备份目录
  `data/plugin_data/astrbot_plugin_session_janitor/backups/` 请保持仅管理员可读；
  已回滚备份也按 `backup.retain` 份数封顶，不会无限增长。

## 配置

可以在面板「设置」页修改，也可以直接编辑 AstrBot 插件配置：

| 配置 | 默认 | 说明 |
|---|---|---|
| `scan.platform_id` | `default` | aiocqhttp 平台实例 ID（面板自动检测并下拉选择） |
| `scan.temp_session_days` | `30` | 临时会话阈值（天） |
| `scan.include_provider_stats` | `false` | 预览是否包含 provider_stats |
| `scan.whitelist` | `[]` | 白名单 UMO / 群号 / QQ |
| `scan.scan_timeout_seconds` | `10` | 群/好友列表超时 |
| `backup.retain` | `5` | 备份保留份数 |
| `automation.auto_clean_enabled` | `false` | 是否开启定时自动清理 |
| `automation.scan_interval_minutes` | `0` | 自动清理间隔（分钟），0 = 不自动执行 |
| `automation.include_provider_stats` | `false` | 自动清理是否包含 provider_stats |
| `notify.enabled` | `true` | 自动清理删除数据后是否发送通知 |
| `notify.targets` | `[]` | 通知 UMO；留空发给数字管理员 QQ |
