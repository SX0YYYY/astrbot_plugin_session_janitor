# 会话清道夫（astrbot_plugin_session_janitor）

一个给 AstrBot 用的核心库清理插件：扫描已退群、已删好友、过期临时会话留下的
会话数据，先预览、再备份、最后删除，并支持一键回滚。

**只操作 AstrBot 核心库 `data/data_v4.db`，不读取、不修改任何插件数据。**
所有管理操作都在 Dashboard 的 Web 面板里完成，不需要记命令。

## 功能

- **扫描**：读取当前 QQ 群/好友列表，对比核心库里的会话数据，自动分类：
  - 已退群：群已不在当前群列表里，默认勾选；
  - 已删好友 / 好友列表外：私聊对象已不在好友列表，默认不勾选；
  - 过期临时会话：好友列表外且超过 30 天未活跃，默认不勾选；
  - 白名单：命中白名单的会话永不清理。
- **会话详情**：群号/QQ号、群名/QQ昵称、UMO、别名、最后活跃时间、各核心表
  残留条数、偏好记录、核心库平台消息历史，以及**可展开查看的核心库完整对话记录**。
- **清理预览**：只读展示“如果清理会处理什么”，支持单独勾选 `provider_stats`。
- **执行清理**：后台任务 + 实时进度；执行前自动做整库快照和逐行 JSON 备份；
  删除在单事务内完成，失败自动回滚。
- **备份与回滚**：每次清理生成一份备份，可在面板里一键回滚。
- **Web 设置**：平台 ID、临时会话阈值、扫描超时、白名单、备份保留份数等
  直接在面板里修改并保存。
- **定时自动清理**：开启后按设定间隔扫描，只清理已退群会话；执行后写日志并按
  通知配置发送摘要。默认关闭，不会自动清理已删好友/临时会话。
- **可见反馈**：刷新、筛选、重新生成、保存、清理等所有按钮都有“处理中/完成/失败”
  状态，不再出现点了没反应的情况。

## 安装

### 从插件市场安装

在 AstrBot Dashboard → 插件 → 插件市场搜索「会话清道夫」安装。

### 手动安装

把整个目录放到：

```text
AstrBot/data/plugins/astrbot_plugin_session_janitor/
```

重启 AstrBot 或在 Dashboard 插件页重载该插件，然后打开：

```text
Dashboard → 插件 → 会话清道夫
```

无需额外 Python 依赖。

## 使用说明

### 四个按钮分别做什么

| 按钮 | 作用 | 会不会重新扫描群列表 |
|---|---|---|
| 开始扫描 | 重新读取当前 QQ 群/好友列表，再扫描核心库，更新所有标签页 | 会 |
| 刷新当前页 | 只重新读取最近一次扫描结果并重画当前页 | 不会 |
| 重新生成预览 | 按当前 `provider_stats` 开关重新计算预览 | 不会 |
| 筛选 | 在最近一次扫描结果里按状态/类型/关键词过滤 | 不会 |

### provider_stats（调用统计）是什么

`provider_stats` 是 AstrBot 每次调用模型时记下的**用量流水**：哪个会话用了哪个模型、
多少 token、耗时多久。删除它只会丢失历史用量统计，**不影响聊天记录、偏好设置、
白名单或机器人运行**。因此默认不清理，需要时在预览/执行清理页单独勾选。

### 清理确认词

执行清理需要输入中文四个字：

```text
确认删除
```

完成后会自动刷新概览、候选列表和备份列表。

### 自动清理

在「设置」页开启「自动清理」，并设置扫描间隔（分钟）。开启后：

- 每隔设定时间扫描一次当前群/好友列表和核心库；
- **只清理「已退群」且仍有核心数据的会话**；
- 已删好友、过期临时会话不会被自动清理；
- 默认不删 `provider_stats`，可在设置里单独打开；
- 删除前照常生成整库快照 + 逐行备份；
- 执行结果写入「扫描日志」，并按通知配置发送摘要。

自动清理默认关闭。设置页会显示当前状态、下次运行时间、上次运行结果。
通知目标留空时，会尝试发送给 AstrBot `admins_id` 里的数字 QQ 管理员；
没有可用的管理员 QQ 时只写日志，不影响清理。

## 常见问题

### 为什么清理后候选列表里还有条目？

它们大概率**只剩 `provider_stats` 调用统计**。该表默认不清理，所以重新扫描后仍会
被识别为候选。新版面板会把这类条目默认隐藏并标注“仅剩调用统计”。

如果你确认要连用量统计一起清掉，勾选「包含 provider_stats」或
「显示仅剩调用统计的条目」，再执行一次清理即可。

### 为什么详情页看不到对话记录？

AstrBot 核心库的 `conversations` 表只保存**真正和机器人进行过 LLM 对话**的会话，
数量通常很少（例如只有 3 条）。QQ 群/好友的普通聊天正文不在核心框架里；
本插件不读取任何插件数据，所以只能显示核心库实际保存的内容。

有记录的会话在会话列表名称旁会显示「有对话记录」标记；点「详情」后可以展开
「查看对话记录」，看到和 Dashboard「数据与日志 → 对话」相同的聊天内容。

### 候选行数是聊天消息条数吗？

不是。它是这个会话在核心库里匹配到的**数据库行数**（会话别名、偏好、调用统计等），
用来判断清理规模，不等于聊天消息数量。

### “已删好友”和“临时会话”怎么区分？

历史数据无法可靠区分两者。插件把好友列表外、未超过 30 天阈值的私聊标为
「好友列表外」，超过 30 天的标为「过期临时会话」，两类都默认不勾选，
需要你手动确认后再清理。

### 会不会误删插件数据？

不会。插件的扫描、详情、清理、回滚都只操作 `data_v4.db`；
`livingmemory`、群日报、`message_stats` 等插件数据一律不读取、不修改。

## 安全设计

1. 扫描阶段数据库只读。
2. 群/好友列表获取失败、超时或返回空列表时立即停止扫描，不产生候选。
3. 只处理 `GroupMessage` / `FriendMessage`；WebChat、系统会话、其他平台跳过。
4. 清理前生成整库快照 + 逐行 JSON 备份；删除单事务，失败回滚。
5. 回滚按逐行 JSON 恢复，不直接替换正在使用的数据库文件。
6. 白名单会话永不清理。

## 配置

可以在面板「设置」页修改，也可以直接编辑 AstrBot 插件配置：

| 配置 | 默认 | 说明 |
|---|---|---|
| `scan.platform_id` | `default` | aiocqhttp 平台实例 ID |
| `scan.temp_session_days` | `30` | 临时会话阈值（天） |
| `scan.include_provider_stats` | `false` | 预览是否包含 provider_stats |
| `scan.whitelist` | `[]` | 白名单 UMO / 群号 / QQ |
| `scan.scan_timeout_seconds` | `10` | 群/好友列表超时 |
| `backup.retain` | `5` | 备份保留份数 |
| `automation.auto_clean_enabled` | `false` | 是否开启定时自动清理 |
| `automation.scan_interval_minutes` | `0` | 自动清理间隔（分钟），0 = 不自动执行 |
| `automation.include_provider_stats` | `false` | 自动清理是否包含 provider_stats |
| `notify.enabled` | `true` | 自动清理删除数据后是否发送通知 |
| `notify.targets` | `[]` | 通知 UMO；留空发给数字管理员 QQ |
